# 开发复盘

TradingCrew 最初是在 TradingAgents 基础上扩展 Web 界面和多市场支持的多智能体研究原型。
后续实验中，值得保留的成果逐渐变成了模型输出周围的程序约束。本次收尾更新把其中三项
重新写成可以独立运行、使用全新虚构数据的离线示例。

维护者将时间转向其他项目，因此暂停主动功能开发。不承诺继续更新模型与供应商兼容性、
行情接口、托管服务或发布计划。原应用作为历史研究代码保留。

## 原始问题由程序保管

模型可能返回格式正确的 JSON，同时遗漏一个不方便回答的问题。仅检查结构不够：
程序需要保存原文与来源位置，为问题生成稳定 ID，再要求模型输出恰好覆盖每一个 ID。
遗漏、重复、编造 ID，或试图在分类结果中改写原文，都会被拒绝。

示例用虚构的车间检查记录演示这个契约。相同作用域内完全相同的原文合并，但保留每一次
来源位置；空白、大小写和 Unicode 表示都不被静默修改。分类标签并不等于问题已经解决，
后续决策仍然需要证据与规则。内容哈希也不是匿名化措施或真实性证明。

## 缺失的用量不能记为零

接口可能只在成功时返回 token 计数，也可能让复用对象保留上一次响应。直接求和会漏掉未知
尝试，或重复计算旧响应。示例要求调用前分配新的 attempt ID，再将响应绑定到实际尝试；
缺失、非法或属于其他尝试的计数保持未知，同时报告已知小计和未知尝试数量。

只有所有纳入统计的尝试都提供了某个字段，才会给出该字段的完整总数。失败调用可能收费，
输入和输出计数也不被拿来补造缺失的总数。示例不估算账单；如果适配器把旧计数错误标成
新 ID，这层约束仍会失效。

## 先检查口径，再做算术

不同币种、数量级、期间、实体或会计口径相除，数值运算正确也可能毫无意义。示例要求这些
元数据明确且相同，才计算两个同期间流量的比率；它不自动换汇、缩放或调整期间。
增长率、估值以及存量和流量之间的比率需要其他语义，不在本例范围内。

标签一致只是必要条件，不能证明原始数据真实，或指标定义在经济意义上可比。这部分仍需
上游核验与人的判断。

## 验证结论必须有边界

冻结的虚构输入便于重复验证；负例检查程序是否拒绝无效结果。输入摘要可以标识重放的是
哪一份字节，却不能证明其来源、发布时间、新鲜度，或历史决策时能否获得这些信息。

多个智能体共享模型与证据，不会自动变成相互独立的审查者。结论一致、JSON 合法、测试数量多，
都不能证明金融判断可靠。离线契约测试与真实模型质量评估回答的是不同问题。

本次更新只验证新增离线示例，没有重跑付费模型、实时行情、旧 Web 应用或交易表现。
旧 README 状态说明之后的模型名单和安装指引描述的是早期实现，不代表本轮已重新验证。

## 本次保留的成果

三项小型契约、一份冻结的虚构输入、一个重放演示，以及成功与拒绝路径测试，足以让后来的
读者复用这些经验。更新保留公开仓原有历史、许可证和上游说明，没有导入私有历史、数据集、
账户状态或本机运维配置。

这些例子独立于原交易引擎，定位为可阅读、可运行、可改编的参考实现，不重新启动研究产品，
也不引入新的通用框架维护承诺。
